# Stage probe 2026-11-04

These are development diagnostics on the unmodified official simulator. There is no score claim. The GDB scripts read registers/memory and continue; breakpoints can perturb timing. `RMUA_STAGE_INIT` is route stage 1–6, not the GameState state value. In `stage_trace.gdb` each `RMUA_TRACE_CLOCK` records host Unix wall and monotonic seconds, followed by the event; ROS wind JSONL records host wall, host monotonic, the ROS message header stamp and vector. `timer_1a8`/`timer_1ac` are raw GameState fields; static analysis shows `timer_1ac` accumulating a game update delta, but its mapping to wall/ROS time has not been calibrated. Neither the ROS header nor these fields should be relabeled wall latency or a fully verified simulation clock.

The controller itself used GPS and IMU and did not subscribe to live debug truth, but **the waypoint provenance is not established to meet the user's truth-only-after-evaluation constraint**. Its raw manifest and logs are preserved, with a correction in `supplementary_environment.json`; its results are not a compliant truth-free navigation run. LiDAR was subscribed but the first-17 route did not execute the LiDAR clearance code.

`seed123_static_sensor`: independent follow-up using only GPS position, IMU orientation/angular velocity, a static cooked-map spline candidate, and LiDAR clearance from waypoint index 2. `static_spline_candidates.json` was produced from `artifacts/maps/maps_summary_all.json` by `scripts/export_static_spline_scout.py`; Hermite tangents, yaw-only component transform, and UE-cm to NED-m conversion are assumptions that require more validation. The script provides only spline 1 and deliberately does not cross an unvalidated hub gap. `/debug/wind` is an observer input only, never a control input.

The runner uses the committed `static_spline_candidates.json`, not the separately exported `/tmp` file. Change the ROS port if in use. The process owns and cleans its uniquely named container. An observer timeout or safety stop is not evidence of a completed stage.

It is not a successful route. Its final GPS sample was approximately [206.2, 0.5, -12.8] m, but some movement occurred after state 12; do not interpret this as the scored endpoint.

The current controller limits horizontal speed to 2 m/s, and in this experiment to 1 m/s during LiDAR checking; it cannot establish a complete stage 1 under the observed deadline by merely increasing its run timeout.
