# 训练环境规格草案与验收门槛

状态：未最终验收。本文是基于 12.0.0.5 的训练环境设计约束，不声明任何现有 episode 管理器或自定义环境已经实现这些约束。已知结果及未完成项以 [验收台账](18_acceptance_ledger.md) 为准；复现环境和原始证据见 [无头要求](16_headless_requirements.md)、[运行记录](17_runtime_validation_20261104.md) 和 [证据索引](09_evidence_index.md)。

## 版本与隔离

- 官方主程序 SHA-256 为 `5231addfa25ddaa9e4473ea9ac40c9c0bc685174e69cd14bb49159f443b97800`；实验 settings 副本与硬件、驱动、Docker 镜像标识见 `experiments/training_host_20261105/`。每个运行记录二进制、settings、镜像哈希、seed、地图、进程身份、端口、墙钟和单调钟。
- 实例之间使用独立 ROS master 和端口；进程退出、响应错误或采样缺口必须留档并使该 episode 失败，不能拼接重试前后的轨迹。`scripts/headless_pool.py` 和 `scripts/run_pool_batches.py` 仅提供空载诊断，不是训练调度器。
- 本机四实例一次完成 345 秒存活及约 300 秒 IMU/LiDAR 连续订阅，七实例另一次在全就绪约 9 秒后退出 139；不得把这两次观察外推为无条件稳定上限。另有四实例固定 PWM 发布和 IMU/LiDAR 观测重叠约 300 秒的单次合成负载，CPU 与源时钟和空载不同；训练部署仍须按实际工作负载、持续时间和资源验证并发数。

## 观测与动作

- 策略在线输入只能使用任务允许的普通观测。可订阅 `/airsim_node/drone_1/imu/imu`、`/airsim_node/drone_1/gps` 和 `/airsim_node/drone_1/lidar`；是否使用相机取决于渲染配置。`debug/pose_gt`、`debug/wind`、`debug/rotor_pwm` 及调试器真值只用于事后评估，不能用于动作或在线就绪决策。
- 记录每条消息的接收单调钟、源 header、序号、类型及配置；源时间为零、相邻重复或回退须显式标记。一次四实例长场出现单条 IMU 零时间戳与多对相邻相等时间戳；不得假定每个 header 都可直接用于差分积分。采样时钟、ROS header 和宿主墙钟不可未经校准直接相减当作端到端延迟。
- NullRHI 的相机 payload 为空；视觉训练必须先验证实际有渲染图像。LiDAR 消息和当前起点的非空点云已观察到，但动态障碍的传感器可见性尚未验收。
- PWM 动作通过 `/airsim_node/drone_1/rotor_pwm_cmd` 发布 `airsim_ros/RotorPWM`；消息 MD5、四个值、顺序、发布时刻和控制周期均须记录。运行时先核对消息类型、参数范围和映射，不能把示例输入范围直接推广为电机物理标定。
- 同主机、单实例的函数钩子实验得到 ROS 发布至接收的有限样本；钩子会影响调度，测得结果不包括物理采样或电机响应。PWM 调试消息的 header 来自单独的 IMU 查询，不能作为 PWM 采样时刻。各实验分布见 `experiments/transport_matrix_20261105/`。

## Episode 生命周期

1. 创建独立实例，核对版本、配置和普通 IMU 就绪；策略和就绪逻辑不能读取调试真值。就绪超时、零时间戳和消息不连续应有显式处置，具体阈值须通过目标负载实验确定。
2. 记录动作与允许的观测，保存消息时间、来源和序号。每个 episode 单独标识；不要假定 ROS 到达时钟等于仿真物理时钟。
3. 服务 `/airsim_node/reset` 的通信成功及 `success: True` 分别记录。已观察到 true 时 API 运动状态仍有瞬态，且实验 true 依赖开发干预；因此 true 本身不能作为物理或随机流已重放的证明。
4. 在原生 reset 未通过完整验证前，对需要独立初始化的训练 episode 使用新进程/容器作为候选流程，并独立验证重启后相同 seed 的场景、状态及目标负载；不把进程重启等同于已验证官方 reset。
5. 仿真退出、服务失败、时钟异常或超出实测负载的情况保留日志并终止该 episode；恢复与重试策略不能悄悄更改 seed 或复用无效状态。

## 地图、随机化和碰撞

- OL1 的 12 门和开发补丁直接加载的 OL2 的 12 门 BeginPlay 已核对；OL2 正常跨图初始化、可飞行性和物理门洞仍未确认。训练器应把地图身份和加载完成证据作为单独记录，不把接收到 ROS 流当作地图已成功切换。
- fresh stage 4/5/6 注入场的风关键帧可由 `scripts/wind_offline_model.py` 在指定随机调用顺序下逐字节重建；正常赛程随机流消耗和原生 reset 后状态不可由 seed 单独假定。线障候选、成功提交实例、车辆路径以及实际接触必须分开建模。
- 粗细线夹具和车辆停车夹具已经观测到来源组件匹配；车辆事件指针已在一场连到游戏回调。这些场景使用注入与状态强制，不能替代自然赛程、碰撞冲量或完整终止行为的验证。

## 最终验收仍需补齐

- 原生或等价开发环境下，运动中的位置、姿态、速度、碰撞/车辆和随机流重置及轨迹重放；明确服务返回和状态稳定的区别。
- 自然线障与车辆接触的动力学和终止链，实际碰撞体/字段的独立类型验证。
- 有明确时长、重复次数及真实训练负载的并发边界，或八实例崩溃的可复现根因。
- OL2 及其他目标地图的门洞几何、可飞行初始化、传感器与世界关联。
- 传感器采样至发布、动作至物理执行的时延和时钟标定；多 seed 渲染及动态障碍传感器数据。
- 在指定硬件、地图、种子、负载及留出样本上验证完整训练器；未达到的项目必须保留为未完成，不能用本草案代替测试结果。
